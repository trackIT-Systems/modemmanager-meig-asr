# Teltonika TRM200 / MeiG SLM770A reference

Hardware and firmware findings from bringing up the TRM200 with ModemManager.
Unless noted otherwise, everything was verified on firmware
`SLM770A_A.57.3_EQ102`. The [README](../README.md) covers installation, the
RNDIS/ECM switch, the port layout, power and the `+ECMDUP` dial; this document
covers the rest.

The [MeiG SLM770A AT command manual](https://wiki.teltonika-networks.com/images/a/a9/MeiG_SLM770A_AT_Commands_Manual_TRM200.pdf)
is published by Teltonika.

## The plugin changes the modem's configuration

When it initializes the modem, the plugin sends:

| Command | Effect |
|---|---|
| `AT+DIALMODE=1` | turns the modem's auto-dial off |
| `AT+DIALCFG="DIALMODE",0` | network-card mode: the carrier IP is passed through to the host |

Both settings are stored in the modem and survive a power cycle.

A factory-new TRM200 dials on its own at power-on and hands the carrier IP to
the host via DHCP. That's why the network works "without control" on systems
without the plugin. Once the plugin has run, the modem no longer does that,
even after the package is removed or the modem is moved to another host.

To restore auto-dial:

```
AT+DIALMODE=0
```

## A factory-new TRM200 without the plugin

`usb0` gets an address and data flows, because the modem dialed by itself. But
ModemManager can't control the modem: it reports the packet service as
*detached*, and connecting through ModemManager/NetworkManager fails. This is
the symptom usually reported for the TRM200 on Linux (e.g. in the Teltonika
community forum). See [Background](../README.md#background) in the README for
the causes.

## USB boot stage

On every real power-on, the modem first enumerates for about 4 s as

```
2ecc:3001 MARVELL WUKONG
```

with one vendor-specific interface and no driver, then re-enumerates as
`2dee:4d57` (RNDIS) or `2dee:4d58` (ECM). This is most likely the ASR boot ROM
and its flashing window: no driver should bind to it. It doesn't appear on a
software re-plug (unbind/rebind or USB port power toggle without the modem
losing power).

## Dial settings

`+DIALMODE` and `+DIALCFG="DIALMODE"` are different settings and easy to mix up:

| Setting | Meaning |
|---|---|
| `AT+DIALMODE=<n>` | auto-dial: `0` the modem dials on its own at power-on, `1` it waits for the host |
| `AT+DIALCFG="DIALMODE",<n>` | network-card mode (`0`, carrier IP passed through to the host) or routing mode (the modem does NAT) |

Routing mode uses its own DHCP pool, configured with `AT^MAPCFG="dhcp"`
(default gateway `192.168.200.1`, pool `.100`–`.200`).

## `+ECMDUP` quirks

Useful when debugging the dial (see the README for why the plugin uses
`+ECMDUP`):

* `+ECMDUP` only works on a context it activated itself. After `+CGACT` it
  fails with `ERROR`.
* `AT+CGACT=1,<cid>` answers `OK` followed by `CONNECT`.
* A second context with the same APN fails with `+CME ERROR: 50`.
* After a re-attach, the modem picks a varying cid for its default bearer
  (1, 2 or 3).
* Mixing `+CGACT` and `+ECMDUP` can leave a hidden binding to `usb0` that
  `+ECMDUP?` doesn't show. Only a modem reboot (`AT+CFUN=1,1`) clears it.

## Unsolicited messages

The modem sends `^SRVST`, `^MODE`, `^SIMST` and `^DCONN`/`^DEND`. By default
they go to all ports (`+URCCFG: ALL`); `^CURCEX` filters them.

## Unsupported commands

This firmware answers `ERROR` to:

* `ATZ`
* `AT+WS46=?`
* `AT+CLAC`
* `AT^LTEATTACHINFO?`
* other vendors' dial commands: `AT$QCRMCALL`, `AT^NDISDUP`, `AT+ZECMCALL`,
  `AT+QNETDEVCTL`, `AT+GTRNDIS`

## Network interface

* The modem answers ARP for every address on the data interface.
* The modem's MAC address on the data interface changes with each session.

## For maintainers

### Raw AT access while ModemManager is running

Inhibit the modem to free its ports:

```sh
mmcli -m any --inhibit
```

The command keeps running; while it does, the AT ports (interfaces 3 and 4, see
the README's port layout) can be used with any serial terminal. Stop it with
Ctrl-C and ModemManager takes the modem back and enables it again (this works
since the `ATZ` fix, patch 0008).

### Testing a change

1. Start from a clean modem state: `AT+CFUN=1,1` reboots the modem and clears
   leftover contexts and bindings (see [`+ECMDUP` quirks](#ecmdup-quirks)).
2. Test data without touching the main routing table: get a lease with a DHCP
   probe (`udhcpc` on `usb0`) and route test traffic through a separate routing
   table.
3. Run the reconnect, restart and re-plug tests listed under
   [Status](../README.md#status) in the README, checking data after each step.
